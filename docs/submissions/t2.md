## 4. Testing Requirements (35 points)

### Unit testing (15 points)

- [x] Cover all major units with unit tests.
- [x] Use test doubles where needed.
- [x] Organize the unit tests into clear groups.
- [x] Name the test runner and provide a single command or action to run the tests.
- [x] Fix most bugs found by unit tests.

### API testing (15 points)

- [x] Test the MVP endpoints with an appropriate API testing tool.
- [x] Keep the API tests in the repository or a linked workspace.
- [x] Organize the API tests into a structured test suite.
- [x] Fix most bugs found by API tests.

### Test coverage (5 points)

- [x] Include a coverage report for the tagged release.
- [x] Verify that the report measures branch coverage.
- [x] Achieve at least **55% branch coverage**.

## 5. External Documentation (20 points)

### README and API documentation (10 points)

The README or linked documentation must cover these items:

- [x] API entry points.
- [x] Inputs and outputs.
- [x] Side effects.
- [x] Status and error codes.
- [x] Call-order constraints.
- [x] Correct usage scenarios.
- [x] Examples of incorrect use.
- [x] Clear and complete build instructions.
- [x] Clear and complete run instructions.
- [x] Clear and complete test instructions.

### Third-party code disclosure (5 points)

- [x] Identify any third-party code in the README, with its location and source URL; if no third-party code is used, state this clearly.

### Project management documentation (5 points)

- [ ] Track tasks for each team member in GitHub Projects, GitHub Issues, or an equivalent tool.
- [ ] Link the task tracker from the README.
- [ ] Give the Mentor and Instructor access if the task tracker is an external tool; otherwise, verify that they can access the repository's tracker.
